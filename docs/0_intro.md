# ВСТУП

## Актуальність теми

Персональні та корпоративні фінансові потоки дедалі частіше розподіляються між гетерогенними сховищами коштів: дебетовими та кредитними банківськими картками, криптовалютними гаманцями та готівкою в кількох валютах. Наявні програмні засоби обліку або прив'язані до екосистеми одного банку, або моделюють мультивалютність як набір ізольованих рахунків без консолідованого балансу. Це спричиняє розбіжність залишків, некоректну конвертацію за неактуальними курсами та неможливість автоматизованого бюджетування на рівні всього портфеля коштів.

Інженерна складність задачі визначається вимогами до консистентності фінансових даних (атомарність операцій, подвійний запис, точна десяткова арифметика), до ідемпотентної асинхронної обробки подій автоматизованого розподілу доходу та до ізоляції даних користувачів у багатокористувацьких сценаріях (сімейний та корпоративний бюджет). Інтеграція LLM-асистента додає вимоги до безпеки доступу моделі до фінансових даних і контролю затримок (Latency) відповіді. Розроблення платформи, що поєднує ці властивості в межах відтворюваного DevSecOps-конвеєра, є актуальною задачею інженерії програмного забезпечення.

## Об'єкт дослідження

Процес обліку, мультивалютної конвертації та автоматизованого розподілу фінансових коштів між гетерогенними гаманцями та бюджетними категоріями.

## Предмет дослідження

Методи та засоби побудови фінансового реєстру за принципом подвійного запису, асинхронної подієвої обробки (Celery, RabbitMQ, патерни Transactional Outbox та Idempotent Consumer), REST API на основі Django REST Framework, клієнтського застосунку на Next.js та інтеграції LLM-асистента з обмеженим read-only доступом до даних.

## Мета роботи

Проєктування та розробка мультивалютної платформи управління фінансами FinJar на основі модульного моноліту Django REST Framework з асинхронним контуром обробки подій для забезпечення консистентності балансів гетерогенних гаманців, автоматизованого розподілу доходу за процентними правилами та скорочення часу ручного фінансового обліку користувача.

## Завдання проєкту

1. Проаналізувати предметну область обліку персональних і корпоративних фінансів та існуючі програмні аналоги за інженерними критеріями.
2. Сформувати функціональні та нефункціональні вимоги до системи відповідно до ISO/IEC/IEEE 29148 і обґрунтувати вибір технологічного стеку.
3. Спроєктувати архітектуру системи за моделлю C4, схему даних фінансового реєстру та REST-контракти OpenAPI 3.0.
4. Розробити алгоритми критичних вузлів: подвійного запису транзакцій, мультивалютної конвертації та ідемпотентного розподілу доходу за баночками.
5. Реалізувати серверну частину на Django REST Framework, клієнтський застосунок на Next.js та LLM-асистента, спроєктувати схему розгортання на основі Docker і GitHub Actions.
6. Провести інструментальний аудит якості програмного коду: модульне та інтеграційне тестування, статичний аналіз SonarQube, сканування вразливостей Trivy, навантажувальне тестування k6.
7. Апробувати результати дослідження у науково-практичній публікації.
